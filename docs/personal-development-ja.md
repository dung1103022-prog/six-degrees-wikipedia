# 個人開発実績: Six Degrees of Wikipedia (Python)

## プロジェクト名 / 概要

**Six Degrees of Wikipedia (Python)** — Wikipedia上のリンクだけを辿り、任意の2人物間の最短経路を求めるWebアプリケーション。英語・日本語どちらの人名入力にも対応。個人開発。

## 開発目的

- 仕様駆動開発(SPEC-driven development)を最後まで一貫してやり切ること
- データベース・常駐ジョブなし、運用コストほぼゼロでも実用に耐える構成にすること
- 英語入力・日本語入力のどちらからでも同じ人物に到達できること

## 自分が担当したこと

個人開発として、以下はすべて自分一人で担当しました。

- 要件定義、アーキテクチャ設計
- 実装仕様書(SPEC.md、全15版)の作成・改訂、および記載されている全トレードオフ判断
- テストケースの設計、SPEC-テスト間トレーサビリティの設計
- 実装内容のレビュー・検証・受け入れ判断

実装(コーディング)そのものはAIコーディングエージェント(Claude Code)に担当させ、自分は設計・指示・レビュー・検証・テスト実行の役割を担っています。ソースコードを一行ずつ自分の手で書いたわけではありません。

## 技術スタック

- **バックエンド:** Python 3.12 / FastAPI 0.141 / Pydantic 2.13(データベースなし)
- **フロントエンド:** React 19 / TypeScript / Vite、Sigma.js 3 + Graphology(グラフ描画)
- **インフラ:** Docker(マルチステージビルド、単一コンテナ運用、ベースイメージはdigest固定、`FORWARDED_ALLOW_IPS`でリバースプロキシ配下のHTTPSスキームに対応)
- **テスト:** pytest / Vitest + Testing Library

## 技術的に工夫した点(4点)

1. **計測に基づく設計変更。** 当初はBFSの進行状況をWebSocketでストリーミングする設計だったが、実測すると約1万ノード規模のBFSはミリ秒単位で完了。ストリーミングは不要と判断し、1回のGETリクエスト+クライアント側アニメーションに置き換えた。
2. **多言語入力とゼロ運用コストの両立。** データベース・実行時のWikipedia呼び出しなしで英語/日本語名を解決するため、エイリアス解決をすべてオフラインのFetcherで事前計算し、実行時はメモリ上の参照のみで完結する設計にした。
3. **リリース後に判明したWindows環境のテスト基盤バグへの対応。** `asyncio` が内部で使うループバックTCP通信をネットワークガードが誤って遮断していた問題を、ガードを広く緩めるのではなく「ループバックアドレスのみ許可」という最小限の変更で修正し、回帰テストを追加した。
4. **単体テストでは検出できないUIバグの発見と修正。** Sigma(WebGL)は設計上モックで隔離しているため、ラベルの重なり・欠けは `vitest` では検出できなかった。実際のChrome + WebGLで目視検証し、ラベルの行数を状況に応じて可変にするアルゴリズムで解決した。

## 成果 / 実績

- 計画していた4フェーズ(データ/BFS/リゾルバー/API → `/share` → Fetcher → フロントエンド/Docker)をすべて実装完了
- 自動テスト **383件**(バックエンドpytest 280件 + フロントエンドVitest 103件)が全件パス。全件がSPEC.mdのテストIDにひも付いている
- 本番用データセットを生成: **9,997人 / 有向エッジ427,057本 / エイリアス119,335件**(曖昧マッチキー0件)
- 実際のアプリケーションをcurl・実Chrome(WebGL)で動作確認: `/api/search`・`/api/people`・`/api/path`・`/share` のレスポンスとグラフ描画を、デスクトップ(1440×900)・モバイル(390×844)双方でコンソールエラー0件で確認
- 直近のメンテナンス対応を `v1.0.1` として反映済み

## 技術的負債・今後の改善

- 未承認のエッジケース(空白のみの入力、255文字超、名前中のアンダースコア)は推測で実装せず、仕様書上「未定」として明示
- 依存パッケージ `anyio` を最新版より1つ前に固定中(`starlette` 側の追従待ちの暫定対応)
- SPEC.md自身の技術的負債セクションが、実際には解決済みの2件(N-1・N-2)の反映にまだ追いついていない
- 名前解決のカバレッジはFetcherが取得した範囲に限定(実行時のライブフォールバックは設計上持たない)
- 検索履歴はブラウザ単位(localStorage)のみで、アカウントや複数端末間の同期はなし(意図的なスコープカット)
